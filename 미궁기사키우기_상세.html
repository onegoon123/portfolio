미궁기사키우기 - 프로젝트 상세

2026-03-13 방치형 RPG Unity 6000.2.8f1, C#, URP, Naninovel, DOTween

프로젝트 개요

미궁기사키우기는 Unity로 개발한 2D 방치형 RPG 프로젝트입니다. 자동 전투로 스테이지를 진행하고, 골드와 경험치를 획득해 캐릭터 스탯을 강화하며, 장비 제작과 동료 해금, 호감도 기반 스토리 해금을 반복 성장 루프로 연결했습니다. 단순 구현 나열보다 실제 플레이 흐름에서 필요한 저장, 오프라인 보상, 오브젝트 풀링, 씬 전환, UI 갱신까지 클라이언트 구조를 직접 설계한 프로젝트입니다.

개발 범위

구분 구현 내용
전투 게임 루프, 자동 전투, 던전 진행, 적 스폰/풀링, 동료 시스템, 장비 제작/장착
스토리 Naninovel 사용 및 커스텀 명령어 제작, Claude Skill를 사용한 시나리오 제작 워크플로우 구성.

기술 스택

  • 엔진: Unity 6000.2.8f1
  • 언어: C#
  • 라이브러리: Naninovel, DOTween, DarkNaku.Number, Cinemachine
  • 디자인: Singleton, Object Pool, Observer

ICombatTarget 기반 전투 타겟팅

문제: 플레이어만 공격하던 적 AI에 동료를 추가하자, 적이 플레이어와 동료 중 가장 가까운 대상을 선택해야 했습니다. 또한 동료는 사망, 씬 전환, 비활성화로 언제든 참조가 끊길 수 있어 null 참조가 발생할 수 있었습니다.
해결: ICombatTarget 인터페이스로 플레이어와 동료를 동일한 전투 대상으로 추상화했습니다. Enemy는 클래스가 아니라 ICombatTarget 배열을 캐싱하고, 공격 전마다 Unity Object 파괴 여부, GameObject 활성 상태, 생존 여부를 확인합니다. 
public interface ICombatTarget
{
    Transform GetTransform();
    bool IsAlive();
    void TakeDamage(int damage);
    int GetCurrentHealth();
    int GetMaxHealth();
    string GetName();
}

방치형 던전 루프

DungeonSystem은 스테이지 시작, 적 생성, 처치 카운트, 스테이지 클리어, 다음 스테이지 진입을 관리합니다. 한 스테이지마다 목표 적 수를 설정하고 EnemySpawner가 풀에서 적을 가져와 생성하며, OnEnemyDefeated 이벤트로 남은 적 수를 갱신합니다.

스테이지가 오르면 StageThemeData의 템플릿을 기반으로 적 데이터를 런타임에 생성하고, 스테이지 수에 맞춰 경험치와 골드 보상을 계산합니다. 플레이어 사망 시에는 던전을 멈추고 체력을 회복한 뒤 자동 전투를 재개하는 흐름까지 포함해 방치형 게임의 중단 없는 진행감을 구현했습니다.

던전 진행 흐름
1. StartDungeon()으로 현재 스테이지 시작
2. SpawnStageEnemies()가 0.5초 간격으로 적 생성
3. EnemySpawner가 Object Pool에서 Enemy를 가져와 데이터 초기화
4. 적 사망 이벤트 수신 후 remainingEnemiesInStage 감소
5. 목표 처치 수 달성 시 NextStage()로 테마/맵/위치 갱신

Object Pool을 적용한 적 생성

방치형 RPG는 적 생성과 처치가 반복되기 때문에 매번 Instantiate/Destroy를 수행하면 GC와 프레임 드랍이 발생하기 쉽습니다. 이를 줄이기 위해 PoolManager에서 Unity 내장 UnityEngine.Pool.ObjectPool을 사용했고, EnemySpawner는 생성 책임과 풀 반환 책임만 맡도록 분리했습니다.

풀링된 적은 재사용될 때 InitializeEnemy()로 체력, 데이터, 콜라이더, HP바, 상태값을 다시 초기화합니다. 이벤트 중복 구독을 막기 위해 스폰 시 기존 구독을 해제한 뒤 다시 등록하는 처리도 넣었습니다.

장비 제작과 스탯 성장

EquipmentCraftingSystem은 제작 포인트를 소비해 무기, 투구, 갑옷, 신발 중 하나를 랜덤 생성합니다.

장비는 등급 확률과 등급 배율을 기준으로 생성되고, 체력, 공격력, 방어력, 공격 속도, 이동 속도, 치명타 확률, 치명타 피해 중 1~4개 스탯을 중복 없이 부여합니다. 착용 장비의 총합 스탯은 EquipmentSystem에서 계산하고, PlayerStats는 기본 성장치와 장비 보너스를 합산해 최종 전투 능력치를 산출합니다.

동료 시스템과 이벤트 기반 연동

CompanionSystem은 동료 해금, 선택, 소환, 호감도, 저장 데이터를 관리합니다. 한 번에 하나의 동료만 활성화하며, 씬 전환 후에도 현재 선택된 동료 ID를 기준으로 다시 소환합니다. 동료가 사망하면 일정 시간 뒤 재소환되도록 처리했습니다.

플레이어 레벨업 이벤트를 구독해 동료 스탯을 현재 플레이어 레벨에 맞춰 갱신하고, 활성 동료가 살아 있는 동안 일정 시간마다 호감도를 증가시킵니다.

저장/로드와 모바일 환경 대응

GameSaveSystem은 플레이어 레벨, 경험치, 골드, 업그레이드 단계, 던전 진행 상태, 장비 슬롯, 동료 상태, 제작 포인트를 JSON으로 저장합니다. 30초 자동 저장 외에도 앱 포커스 해제, 일시정지, 종료 시점에 저장을 수행해 모바일 환경에서 진행 데이터가 손실될 가능성을 줄였습니다.

저장 데이터에는 saveVersion을 포함해 기능 확장 시 이전 저장 파일과의 호환성을 고려했습니다. 골드는 DarkNaku.Number를 문자열로 저장해 방치형 게임 특유의 큰 수 표현과 직렬화 문제를 함께 해결했습니다.

Naninovel 스토리 시스템

블루아카이브, 니케 등 서브컬쳐 게임을 레퍼런스로 게임 내 스토리 컨텐츠를 구현했습니다
Naninovel 에셋을 사용해 기본 비주얼노벨 시스템을 이용하며 추가로 필요한 기능은 커스텀 명령어를 구현하여 사용했습니다.

한국어 조사 처리 명령어

플레이어 이름이 변수로 들어가면 받침 유무에 따라 “은/는”, “이/가”가 달라집니다. @jong 명령어에서 마지막 글자의 종성 여부를 계산하고 올바른 조사를 Naninovel 변수에 저장하도록 했습니다.

CommandAlias("jong")]
public class JongsungCheck : Command
{
    [ParameterAlias("text")]
    public StringParameter SourceText;

    [ParameterAlias("with")]
    public StringParameter WithBatchim;

    [ParameterAlias("without")]
    public StringParameter WithoutBatchim;

    [ParameterAlias("set")]
    public StringParameter TargetVariable;

    public override UniTask Execute(AsyncToken token = default)
    {
        var text = Assigned(SourceText) ? SourceText.Value : string.Empty;
        var particle = HasFinalConsonant(text) ? WithBatchim.Value : WithoutBatchim.Value;

        var variables = Engine.GetService<ICustomVariableManager>();
        variables.SetVariableValue(TargetVariable, new(particle));

        return UniTask.CompletedTask;
    }

    private static bool HasFinalConsonant(string text)
    {
        var lastChar = text[text.Length - 1];
        var code = lastChar - 0xAC00;
        return code % 28 != 0;
    }
}

스토리 종료 후 전투 복귀

스토리 감상은 별도 씬에서 진행되지만, 에피소드가 끝나면 플레이어가 바로 메인 전투 화면으로 돌아와야 합니다. 이를 위해 @end 명령어를 만들고, Naninovel 스크립트 마지막에서 Unity의 main 씬을 비동기로 로드하도록 연결했습니다.

[CommandAlias("end")]
public class SwitchToAdventureMode : Command
{
    public override async UniTask Execute(AsyncToken asyncToken)
    {
        var opMain = SceneManager.LoadSceneAsync("main");
        await UniTask.WaitUntil(() => opMain.isDone);
    }
}

또한 Claude Code 커스텀 스킬 형태의 시나리오 변환 규칙을 설계해 자연어 시나리오를 Naninovel 스크립트로 변환하는 워크플로우를 구성했습니다. 반복적인 스크립트 문법 작성 비용을 줄이고, 스토리 초안을 실제 게임 연출로 빠르게 옮기는 데 초점을 맞췄습니다.

데이터 중심 설계

캐릭터, 적, 던전, 스테이지 테마, 아이템은 ScriptableObject 기반 데이터로 분리했습니다. 또한 CSVReader와 GameDataLoader를 통해 StreamingAssets의 CSV 데이터를 읽어 플레이어 스탯, 적 스탯, 게임 설정 값을 로드할 수 있도록 구성했습니다.

밸런스 수치를 코드에 고정하지 않고 데이터로 분리해, 전투 공식이나 UI 로직을 건드리지 않고도 성장 곡선과 보상 값을 조정할 수 있게 했습니다. 신입 클라이언트 개발자로서 코드와 데이터의 경계를 의식하고 설계했다는 점을 보여주는 부분입니다.

주요 성과

  • 실제 Unity 프로젝트 단위 구현: 씬, 프리팹, ScriptableObject, 패키지, 저장 파일까지 포함한 완성형 클라이언트 구조 구성
  • 전투 확장성 확보: ICombatTarget으로 플레이어와 동료를 동일한 전투 대상으로 추상화
  • 성능 고려: Unity 내장 ObjectPool을 활용해 적 반복 생성 비용과 GC 부담 완화
  • 이벤트 기반 구조: 레벨업, 스탯 변경, 동료 변경, 스테이지 클리어를 C# event로 연결해 결합도 감소
  • 모바일 플레이 고려: 자동 저장, 앱 일시정지 저장, 오프라인 제작 포인트 회복, SafeArea UI 적용
  • 스토리와 전투 연결: Naninovel 커스텀 명령어로 한국어 조사 처리와 스토리-전투 씬 전환 구현
  • 면접 설명 가능한 설계: Singleton, Facade, Observer, Object Pool, Interface, Data-Driven Design을 문제 해결 맥락에서 적용
