와일드 템페스트 - 프로젝트 상세

모바일 서바이벌 액션 Unity 2022.3 LTS, C# GPGS, AdMob, Unity IAP

프로젝트 개요

와일드 템페스트는 모바일 환경을 목표로 제작한 2D 톱다운 서바이벌 액션 게임입니다. 플레이어는 이동에 집중하고 무기는 자동으로 공격하며, 전투 중 획득한 경험치로 무기와 액세서리를 선택해 빌드를 완성합니다. 단순한 전투 구현에 그치지 않고, 대량의 적과 투사체가 동시에 등장하는 장르 특성을 고려해 객체 풀링, 데이터 기반 밸런싱, 로컬/클라우드 저장, 광고와 결제 연동까지 하나의 모바일 게임 사이클로 구현했습니다.

전투 및 아이템 시스템

무기, 액세서리, 진화 아이템을 하나의 인벤토리에서 관리하되, 각 아이템의 동작은 개별 클래스에 분리했습니다. ItemBase는 쿨다운과 레벨 구조를 담당하고, 무기 클래스는 Activate()를 오버라이드하여 화염구, 검, 번개, 메테오 등 서로 다른 공격 방식을 구현합니다.

[아이템 상속 구조]
ItemBase (추상 기본 클래스)
├── WeaponBase
│   ├── Fireball, Sword, TripleLightning, Meteor
│   ├── Axe, Staff, Grimoire, FrostMine
│   └── Evolution()으로 무기 진화 처리
└── Accessory
    ├── AttackRing, SpeedBoots, Robe, Quiver
    └── Book, DarkRing, Hourglass, Accessory
public abstract class ItemBase
{
    public virtual void Tick()
    {
        cooldownTimer -= Time.deltaTime;
        if (cooldownTimer < 0)
        {
            if (Activate())
                cooldownTimer = cooldown * (1.0f - cooldownReduction);
        }
    }

    public virtual bool Activate() { return false; }
    public abstract void OnEquip();
    public abstract void LevelUp();
}

PlayerInventory는 아이템 코드를 생성 함수와 매핑하는 팩토리 구조를 사용합니다. 새 무기를 추가할 때 생성 로직을 여러 곳에 흩뿌리지 않고, 아이템 코드와 클래스 등록만으로 인벤토리 시스템에 연결되도록 설계했습니다.

레벨업 및 진화 시스템

레벨업 보상은 현재 보유 아이템, 무기/액세서리 슬롯, 최대 레벨 여부, 진화 조건을 함께 고려해 후보를 구성합니다. 무기가 최대 레벨이고 필요한 액세서리를 보유한 경우에만 진화 아이템이 후보에 들어가도록 하여, 무작위 선택 안에서도 플레이어의 성장 상태가 반영되게 했습니다.

public bool CanEvolution(int id)
{
    var data = Wild.Item.Data.DataMap[id];
    int weapon = data.EvolutionWeapon;
    int accessory = data.EvolutionItem;

    if (items.TryGetValue((ItemCode)weapon, out var item))
    {
        if (item is WeaponBase weaponItem && weaponItem.isEvolution)
            return false;
    }

    return IsMaxLevel(weapon) && ContainsItem(accessory);
}

오브젝트 풀링 시스템

문제: 서바이벌 장르는 적, 투사체, 경험치 오브젝트, 이펙트가 짧은 시간 안에 반복 생성됩니다. 모바일 환경에서 Instantiate/Destroy가 누적되면 GC와 프레임 드롭이 쉽게 발생합니다.
해결: 프리팹 이름을 키로 사용하는 ObjectPoolManager를 만들고, 각 풀은 Queue<GameObject>로 대기 객체를 관리했습니다. Poolable의 OnSpawn/OnDespawn 훅으로 재사용 시 초기화와 정리 로직을 분리했습니다. 
public class ObjectPool
{
    public Queue<GameObject> queue = new Queue<GameObject>();

    public GameObject Get()
    {
        GameObject obj;
        if (queue.Count > 0)
            obj = queue.Dequeue();
        else
        {
            obj = GameObject.Instantiate(prefab, parent);
            obj.GetComponent<Poolable>()?.Init(o => Return(o));
        }

        obj.SetActive(true);
        obj.GetComponent<Poolable>().OnSpawn();
        return obj;
    }

    public void Return(GameObject obj)
    {
        obj.SetActive(false);
        obj.GetComponent<Poolable>().OnDespawn();
        queue.Enqueue(obj);
    }
}
결과: 반복 생성 비용을 줄이고, 적과 투사체가 많아지는 상황에서도 프레임 안정성을 확보할 수 있는 구조를 만들었습니다.

데이터 저장 및 서비스 연동

게스트 플레이와 Google 계정 플레이를 모두 지원하기 위해 저장 경로를 분리했습니다. 게스트는 PlayerPrefs에 저장하고, Google 로그인 상태에서는 GPGS 클라우드 저장을 호출합니다. 앱 일시정지와 종료 시점에 자동 저장을 수행하여 모바일 환경에서 데이터 손실 가능성을 줄였습니다.

public static void Save()
{
    switch (GameManager.Instance.type)
    {
        case SigninType.guest:
            data.SaveLocal();
            break;
        case SigninType.google:
            if (PlayGamesPlatform.Instance.IsAuthenticated())
                GPGSManager.Instance.Save(data);
            break;
    }
}
